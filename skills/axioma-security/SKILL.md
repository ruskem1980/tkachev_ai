# AXIOMA Security — аудит сайта и соответствия 152-ФЗ

## Что это

Единый порядок глубокой оценки веб-ресурса: техническое тестирование, проверка обработки
персональных данных, стоимостная оценка риска со ссылкой на конкретную норму и санкцию. Аудит
доказывает три вещи и оценивает их в рублях:

- **можно ли извлечь данные** — какие поля, каким усилием, какой объём;
- **нарушает ли ресурс закон** — 152-ФЗ, 242-ФЗ, требования РКН, с привязкой к статье и вилке штрафа;
- **сколько это стоит** — ожидаемый ущерб по сценарию и приоритет устранения.

Каждая находка несёт: доказательство (запрос или снимок), затронутые данные, норму, вилку штрафа,
стоимость устранения, приоритет (P0/P1/P2).

## Когда применять

- Аудит или пентест сайта Заказчика либо собственного ресурса.
- Проверка сайта на соответствие 152-ФЗ и требованиям РКН к сайтам.
- Оценка риска утечки ПДн и перевод риска в деньги для собственника.
- Обследование конкретного домена перед письмом Заказчику о слабых местах.

## Шаг 0 — авторизация (до любого активного запроса)

**Активный тест без письменного разрешения владельца недопустим** — подпадает под ст. 272 УК РФ
(неправомерный доступ). До первого активного запроса фиксируется scope (домены и поддомены), окно
теста, IP источника, разрешён ли нагрузочный тест и отправка данных в формы, кому немедленно
эскалируется критическая находка. Пассивная разведка по открытым данным допустима; граница — первая
попытка обойти ограничение доступа.

**Нет разрешения — не тупик, а развилка.** Без письменного согласия выполняется и сдаётся
**пассивно-документарный аудит**: этапы 1 (только пассивная разведка), 2, 4 по видимому, 5 по
документам. В отчёте явно указывается, что активные этапы 3 и 13 не проводились из-за отсутствия
авторизации. Шаблон листа согласования (scope, окно, IP, разрешённые действия, контакт эскалации)
готовится на этом же шаге.

**Красный флаг — СТОП:** активное сканирование чужого ресурса без разрешения; расширение scope на
поддомен, которого нет в согласовании; нагрузочный тест без явного разрешения.

## Порядок работ

Строго по этапам, каждый закрывается артефактом. Полное содержание каждого этапа, чек-листы и
таблицы — в [references/methodology.md](references/methodology.md).

| Этап | Содержание | Артефакт |
|---|---|---|
| 0. Подготовка | Scope, разрешение, инвентаризация активов | Карта активов, лист согласования |
| 1. Пассивная разведка | OSINT, DNS, поддомены, стек, утёкшие данные, subdomain takeover, SPF/DKIM/DMARC | Реестр поверхности атаки |
| 2. Транспорт и заголовки | TLS, сертификаты, заголовки безопасности, cookie | Таблица заголовков и оценок |
| 3. Приложение | OWASP: инъекции, XSS, IDOR, авторизация, CSRF, API, JWT/OAuth, request smuggling, CVE | Реестр технических находок |
| 4. Персональные данные | Что собирается, где хранится, что утекает, потоки во внешние сервисы | Карта потоков ПДн |
| 5. Соответствие 152-ФЗ | Документы, согласия, локализация, cookie, трансграничка, обработчики, модель угроз | Матрица соответствия |
| 6. Стоимость риска | Ущерб по сценариям, привязка к штрафам, CVSS | Таблица санкций и приоритетов |
| 7. Отчёт | Сводка, план устранения, приложения | Премиум DOCX |

**Этап закрыт**, когда его чек-лист в методологии пройден полностью и всё непокрытое названо явно
(«порт X не проверялся — вне окна»). Незакрытый этап не пропускается молча.

Расширенная техническая поверхность (открытые сервисы и БД, публичные облачные хранилища, обход
CDN/WAF, supply-chain фронта, секреты в бандлах) и модель угроз по ФСТЭК/ФСБ — в методологии,
разделы 13–16.

## Стоимостная оценка и нормы

Стоимость риска = вероятность × (штраф + прочий ущерб). Штраф берётся по действующей редакции,
к расчёту — середина вилки. Полный справочник санкций (КоАП ст. 13.11, УК ст. 272.1, требования
152-ФЗ, ФСТЭК/ФСБ, сроки уведомлений) — в [references/fines-152fz.md](references/fines-152fz.md).

Ни одной суммы штрафа в теле скила — единственный источник цифр — справочник
`references/fines-152fz.md`; из него берётся вилка под состав, к расчёту — её середина.

**Множитель вероятности** (перевод «сложности эксплуатации» в число для умножения на рубли):

| Вероятность | Множитель | Критерий |
|---|---|---|
| Высокая | 0,7 | Эксплуатируется без аутентификации, готовым инструментом, в один шаг |
| Средняя | 0,4 | Нужна учётная запись, цепочка из нескольких шагов или подбор |
| Низкая | 0,1 | Требуется редкое условие, инсайдерский доступ или сложная цепочка |

**Сквозной пример:** открытая выгрузка с данными 30 000 субъектов → состав ст. 13.11 ч. 13,
середина вилки 7 500 000 ₽ → эксплуатация без аутентификации, множитель 0,7 → стоимость риска
5 250 000 ₽ + прочий ущерб (простой, разбирательство) → приоритет P0.

**Агрегация в сводку:** итог сайта = сумма ожидаемых ущербов по независимым составам; штрафы по
одному составу не суммируются между собой (берётся максимальная вилка). В сводку — топ-5 по рублям.

Каждой технической находке присваивается балл CVSS (3.1 или 4.0) поверх приоритета; доступ к ПДн
поднимает приоритет независимо от базового балла. Типовые базовые векторы по классам находок — в
методологии, раздел 16.

## Выдача отчёта

Итоговый документ — **премиум DOCX AXIOMA**. Оформление, генерация и обязательные проверки файла —
**REQUIRED:** скилы `axioma-docx` и `axioma-tables`. Если оба недоступны — сдаётся markdown-отчёт по
структуре ниже, с пометкой, что финальное оформление — через `axioma-docx`.

**Два разных запрета, не путать.** (а) Взаимодействие с целью аудита и публичные OSINT-источники
(журналы прозрачности сертификатов, базы утечек, каталоги CVE, DNS домена) — **разрешены**, без них
аудит невозможен. (б) Выгрузка **собранных данных Заказчика** во внешние сервисы — LLM-облака,
онлайн-сканеры, песочницы — **запрещена**; собранное остаётся в периметре, состав и адресаты
фиксируются в журнале.

Структура отчёта: сводка для руководителя (3–5 рисков в рублях) → карта поверхности атаки → реестр
технических находок с доказательствами → карта потоков ПДн → матрица соответствия 152-ФЗ → таблица
санкций и стоимости риска → приоритетный план устранения → приложения (проверенное, отклонённые
гипотезы, версии и CVE).

## Реестр находок — фиксированные колонки

Одна строка на находку, колонки не менять:

| № | Находка | Класс | Доказательство | Затронутые ПДн | Норма | CVSS | Штраф (середина) | Множитель | Риск, ₽ | Устранение | Приоритет |
|---|---|---|---|---|---|---|---|---|---|---|---|

Образец строки: `1 | Нет CSP | XSS-риск | curl -I (нет заголовка) | поля формы обратной связи |
ст. 13.11 ч. 2 | 6.1 | 500 000 | 0,4 | 200 000 | 6 ч фронтенд | P1`.

## Порядок проверки перед выдачей

1. Каждая находка воспроизведена дважды, доказательство приложено.
2. Каждая сумма штрафа сверена с действующей редакцией КоАП на дату отчёта.
3. Объём затронутых субъектов посчитан, а не назван словом — от него зависит часть статьи и штраф.
4. Гипотезы без воспроизведения вынесены в отдельный раздел, не смешаны с находками.
5. После устранения — повторный тест каждой находки; статус «исправлено» только по ретесту.
6. Документ прошёл проверки скила `axioma-docx` и открывается получателем.

## Частые ошибки

| Ошибка | Как правильно |
|---|---|
| Активный тест без письменного разрешения | Сначала scope и разрешение (ст. 272 УК) |
| Находка из сканера без ручной проверки | Сканер даёт кандидатов; в отчёт — после воспроизведения |
| «Утекло N» без подсчёта объёма | Посчитать субъектов: объём определяет часть ст. 13.11 |
| Проверена только витрина сайта (политика, cookie) | Проверить ядро: модель угроз, локализацию, обработчиков, меры ФСТЭК |
| Штраф назван по памяти | Сверить с действующей редакцией; часть статьи — по первоисточнику |
| «Исправлено» со слов Заказчика | Статус только по повторному тесту |
